# 정상 후보 수집 전 운영 점검

이 명령은 수집 전에 실제 수신·처리 경계·서비스·시간 동기화·등록 상태·공간을 읽어 확인한다. 서비스·기기·정책·모델·Checkpoint는 변경하지 않는다. 출력 보고서만 새 Git 제외 경로에 기록한다.

운영 점검 통과와 본 수집·학습 가능 여부는 구분한다. 펌웨어/P0 출처, 기기별 실제 추론·실행 모델, 공식 편입·Profile별 QC, 새 그룹 배정과 종료/재개 적격성을 이 명령만으로 인증하지 않는다. 후보 Manifest와 학습·전체 Session 승인 false는 그대로 보존한다.

## 실행

검토된 명령이 있는 Checkout을 사용하며 운영 Checkout을 작업 Directory로 둔다. 같은 환경 설정으로 세 관측을 읽고 여섯 처리 경계가 두 차례 전진하는지 검사한다. 기본 관측 간격은 12초이며 결과는 `PASS` 또는 `HOLD`다. `HOLD`는 종료 코드 1, 인자 파싱 오류는 2를 반환한다.

```bash
cd /home/pi/iot-edge-zero-trust
venv/bin/python -m edge.features.normal_collection_preflight \
  --project-root /home/pi/iot-edge-zero-trust \
  --device esp32_01 --device esp32_02 --device pico_01 \
  --required-free-bytes 8589934592 \
  --report output/precollection-new-run/runtime-preflight.json
```

보고서는 새 파일로만 생성한다. 기존 파일·원본 자료·Symbolic Link 경로를 덮어쓰지 않는다. 설정의 전체 내용, 비밀번호·인증 키, MQTT Payload·UART 원문과 traceback은 보고서에 담지 않는다.

운영 Checkout에 명령이 아직 없으면 검토된 파일 하나를 `output/<새 디렉터리>/normal_collection_preflight.py`에 두고 위 예시의 `-m edge.features.normal_collection_preflight` 대신 해당 파일 경로로 실행한다. 이 경로는 운영 서비스 코드 배포와 구분한다. 실행 코드와 실제 운영 Commit을 각각 기록한다. 보고서는 해당 프로젝트의 Git 제외 `output/` 아래 새 `.json`이어야 한다.

구성 정보는 점검 프로세스가 읽은 설정이다. 실제 서비스 프로세스가 같은 AI 모드·모델을 사용한다는 완료 증거로 바꾸어 표현하지 않는다. 비활성 MQTT IF의 오래된 Checkpoint는 활성 장애로 세지 않는다. 실행 Stage가 현재 후보 collector의 고정 여섯 처리 단계와 맞지 않으면 수집을 진행하기 전에 collector를 보완한다.

각 관측은 SQLite 읽기 전용 트랜잭션을 사용한다. 세 기기의 15초 이내 수신, ACTIVE·normal 상태, 시간 동기화, 필요한 수집·처리 서비스, Commit·Boot·Session·IP·정책·Trust의 유지와 추적 파일 변경 여부를 확인한다. 여섯 Checkpoint는 실제 `source_table`, 45초 이내의 10초 경계, 두 차례 전진 및 처리 ID 역행 여부를 검사한다. 이 15초/45초는 짧은 운영 점검의 시간 예산이며 정상 Profile QC나 Rule 경곗값이 아니다.

## 결과를 사용하는 순서

1. 보고서의 운영 점검 결과와 HOLD 사유를 확인한다. 오류·결측·미확인은 정상이나 0으로 보정하지 않는다.
2. 별도로 선택 범위·출처·공식 편입·기기/Profile QC의 사본 시험 결과를 연결한다.
3. 현재 Session 108은 개발 그룹으로 보존한다. 실제 새 Boot·Session의 계획 재개와 입력·처리 전진을 검증한 뒤 T1·T2·V1·V2 슬롯을 연결한다.
4. 매 수집 직전에 운영 점검과 보존 공간을 다시 확인한다. 수집·재개 도중 배포·공격·격리·복구 시험을 섞지 않는다.

처리 경계 전진은 Stage 공통 관측이다. 입력이 없거나 정상 판정으로 이벤트가 없는 구간, 특정 기기의 OFF·품질 제외와 정상 추론 완료를 이 결과로 서로 같게 취급하지 않는다. 개별 완료·실제 모델 증거는 별도 실행 기록 계약으로 관리한다.
